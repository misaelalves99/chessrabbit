# Contribute to ChessRabbit during Hacktoberfest 2026

ChessRabbit welcomes contributors in October and throughout the year. Help improve a free Windows chess application with local storage, Stockfish, Leela Chess Zero and other UCI engines.

## What changed in 2026

According to the [official Hacktoberfest FAQ](https://hacktoberfest.com/questions), pull requests and merge requests no longer count toward Hacktoberfest rewards. The 2026 event uses online challenges, learning activities and local events instead. Repository topics and issue labels are discovery aids, not official registration, endorsement or a guarantee of rewards. ChessRabbit is an independent project.

If you want to participate in the official event, follow [Hacktoberfest's registration and activity instructions](https://hacktoberfest.com/). Your personal event registration is separate from contributing here.

## Choose useful work

- [Good first issues](https://github.com/shivamjg101/chessrabbit/issues?q=is%3Aissue%20is%3Aopen%20label%3A%22good%20first%20issue%22): bounded tasks with starting files and acceptance criteria.
- [Help wanted](https://github.com/shivamjg101/chessrabbit/issues?q=is%3Aissue%20is%3Aopen%20label%3A%22help%20wanted%22): work that benefits from community testing and implementation.
- [Discussions](https://github.com/shivamjg101/chessrabbit/discussions): setup questions and ideas before a larger change.

Follow [CONTRIBUTING.md](../CONTRIBUTING.md) to fork, set up a development environment and open a pull request against `main`. Comment on an issue before starting to help avoid duplicate work. Ask questions if the scope or acceptance criteria are unclear.

Useful contributions include accessibility fixes, reliable error/loading states, regression tests, reproducible bug reports and documentation tested on your own machine. A small verified fix is valuable. Keep changes focused; preserve users' saved games and the project's free features.

## Review expectations

Maintainers review correctness, relevance, licensing and evidence of testing. Contribution volume does not guarantee acceptance. Do not submit generated changes you cannot explain, unrelated rewrites, copied unlicensed material or cosmetic churn solely to increase contribution counts. Never commit credentials, private games or unlicensed engine/network files.

Do not use `hacktoberfest-accepted` labels or automated approvals to imply reward eligibility under the 2026 rules. For security vulnerabilities, follow [SECURITY.md](../SECURITY.md) instead of opening a public report.
